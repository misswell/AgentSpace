# 0.1.68 — 打开应用复用桌面模式的输入、画面和帧率链路

先「检查更新」，关闭并重新打开应用窗口。本次为 App 端调整，无需重装助手。设置里的「帧率」与桌面窗口的帧率选择现在控制同一项设置。

鼠标模式调整为「自动／接管／点击后接管」：「接管隐藏鼠标」更名为「自动」，仍然即时跟随并只显示外部鼠标；原先等待鼠标停顿的「自动」已移除。旧「自动」的保存设置直接清除，不做迁移。

打开应用原先保留独立的鼠标调度、键盘入口和低帧率设置，即使已有共享的视频传输，操作节奏仍与桌面不同。本次将两个入口统一：

- 同一个 RemoteSurfaceView、RemoteViewerInput 和持久输入通道，鼠标按下、拖动、松开即时发送，点击不再等松开后才开始处理。
- 同一个定时补发机制：一连串移动结束后，最后一个位置也能准时送达，无需等待下一次移动或视频帧。
- 同一个键盘转发规则、鼠标显示模式、显示质量和自适应帧率策略。移除单独的应用 5/10/15 FPS 限制，应用窗口采用桌面帧率设置，拖动和滚动仍可提升到 60 FPS。
- 关闭后再次打开会重新连接同一输入链路并获得键盘焦点，避免旧代码关闭通道后退回 RPC 的慢路径。
- 窗口身份、单窗口画面采集及坐标映射仍用于定位对应应用；输入校验与后台会话限制保持有效。远端鼠标的全局位置现在正确转换成应用窗口内的位置。

回归测试覆盖同一真实输入 socket 上的桌面与应用两种目标、末次移动补发、即时按下以及关闭一个窗口后另一个窗口继续使用通道。证据见 `docs/validation.md` §368。
