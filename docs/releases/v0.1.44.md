# 0.1.44 — 桌面点击不再依赖易变的显示器编号

修复 0.1.43 的一个回归：打开桌面后点击无反应、连点也没用。原因是 0.1.43
把点击目标钉在了显示器编号上，而 macOS 的显示器编号会变——这台 Mac 上实测
一个下午内从 22 变成 58（显示器休眠、重枚举都会变）。编号一变，Worker 就以
「请求的 Retina 显示器已不可用」拒绝每一次点击。

现在点击目标是「会话当前的 2× 屏幕」这个**角色**，不再携带编号：Worker 在
每个数据包到达时现场解析当前的 2× 屏幕（与状态栏、采集用的是同一份数据），
照旧校验坐标并加上屏幕原点。采集侧同理：请求的编号不存在时，回退到当前的
2× 屏幕再开流。显示器编号从此对 App 不可见，这一类失效整体消失。

**更新后需让 Worker 同步到 0.1.44**（App 会在前台自动尝试，可能要求管理员
授权；或使用「重新安装助手…」）。旧的 0.1.43 Worker 不认识新的目标类型，
会拒绝点击，所以两边都要更新。

关于 Dock 的说明：本次测量发现 Agent 会话里 Dock 进程当时没有运行（已手动
启动），macOS 也只把 Dock 画在会话的主屏（1×）上——2× 屏即使开启「显示器
各有独立空间」也没有 Dock（已实测并还原设置）。打开 2× 桌面看不到 Dock 是
系统排列使然，不是采集缺失。

本地单元测试、MCP、更新器与 Agent 会话界面检查通过。点击链路在 Agent 会话
内实测：一次点击恰好在会话事件流中产生一次按下、一次松开（clickState=1），
TextEdit 关闭按钮真实关闭。正式包由 CI 签名、公证并发布。
