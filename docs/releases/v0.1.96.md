# 0.1.96 — ⌘V 把网页上复制的那段文字、Finder 里复制的那个文件夹，粘进 Agent 桌面

**更新 AgentSpace 到 0.1.96，然后用一次「重新安装助手…」把 Worker 对齐。** 这一次
**Worker 变了**：它多了 `clipboard.push` / `clipboard.pull` 两个方法，`status` 里也多一个
`clipboard` 块。助手和 Worker 都是按版本号比对的，所以先按一次「重新安装助手…」并允许一次
macOS 管理员授权——它会停掉旧的守护进程、注册这个版本里的助手；应用随后会像往常一样核对
已连接账号的 Worker 版本，用这条既有路径把 0.1.96 的 Worker 装进去（账号页的「更新 worker…」
是同一件事的手动入口）。这只是把版本对齐，不影响登录、桌面或已有的连接，也不需要重新登录。
先手动按一次，只是让「Worker 已经是 0.1.96」在下面这些行为之前就是确定的事实。

**因此：在 Worker 换成 0.1.96 之前按 ⌘V，是「和以前一样」，不是报错。** 旧的 Worker 对这两个
方法回答 `METHOD_NOT_FOUND`，应用把它认成「Worker 是旧的」，于是这一次和以后每一次 ⌘V 都
原样转发给 Agent——也就是这次更新之前的行为，由 Agent 自己的剪贴板应答。代价是**每个账号
一次**：第一次会多一个来回（那一次的回答就是 `METHOD_NOT_FOUND`），并显示一行提示
「更新这个账号的 Worker，才能在它的桌面里用 ⌘V 粘贴文字和文件。」；之后这个账号的每个窗口
都不再尝试，直接原样转发。账号页（Worker 正在运行时）「剪贴板粘贴」那一行会写「当前 Worker
不支持」。没有任何东西会失败，也不会有粘贴被吞掉——这是「旧 Worker 降级成旧行为」，不是
「旧 Worker 报错」。

**这一版做了什么。** 在「打开桌面」窗口和每一个 Fusion 窗口里，⌘V 现在会把你在 Mac 上
复制的**纯文字和文件**送进 Agent 的桌面，⌘C 把 Agent 复制的东西送回你的剪贴板。Finder 里
复制的文件夹算一项，整个文件夹一起过去；在源文件里选中一段文字也一样。这是产品第一次把
两个桌面之间的剪贴板接起来——以前只有 Agent 自己的文字剪贴板（0.1.82 的
`clipboard_read` / `clipboard_write`），人的剪贴板从来没有接上过。

**它只在按键那一刻工作，不是镜像。** 你的剪贴板在你按下 ⌘V 的那一瞬间被读一次，写入发生在
⌘C 且 Agent 的剪贴板**确实变了**之后；没变就完全不碰你的剪贴板，所以你粘的永远是你刚复制的
那一次。整个过程没有轮询、没有定时器，也没有「让两边的剪贴板保持一致」这种东西。

**文件是值过去的，不是路径过去的。** Agent 账号读不到你的个人目录，所以文件不能以路径的
形式交过去：字节被暂存在这个账号自己的 runtime 目录下的 `clipboard/` 里——那是两个用户都能
到达的目录，靠的正是它那份双用户继承 ACL（和 socket、token、截图用的是同一份）。`inbox/`
是一次请求的字节，搬完就删；`pasted/` 是 Agent 剪贴板指向的那份，所以十分钟后再粘贴仍然
找得到那个文件；`outbox/` 是 Worker 对 Agent 那边文件的副本，应用会再复制一份到自己
`~/Library/Caches/com.agentspace.AgentSpace/Clipboard/` 才放到你的剪贴板上，所以 Agent
之后再复制别的东西，也不会把你还没粘的那次内容抽走。

**上限。** 文字 1 MiB（和 `clipboard.read` / `clipboard.write` 同一个数字，超过就明说，
不会悄悄截断）；文件和文件夹每次最多 32 项、128 MB；每一侧保留 8 批或 512 MB，七天没动过的
批会被清掉，但**最新的一批永远不删**，因为那正是下一次粘贴要用的一批。

**没有带过来的：** 图片和富文本。这种剪贴板的 ⌘V 仍然会送到 Agent，由 Agent 自己的剪贴板
应答——和这个功能存在之前一模一样——同时你会被告知一次这个内容没有被带过去。这句话是提示，
不是报错：按键确实到位了，把一次成功的粘贴显示成红色只会让人不再信任它。同样的处理适用于
超过 1 MiB 的文字、超过 32 项的选择，以及上面那个旧 Worker 的情形：**任何一条路径上，⌘V
都不会被吞掉**，因为「按了没反应」是这个功能唯一不能引入的 bug。

**符号链接不搬。** 链接是唯一一种会把「路径」而不是「字节」带过边界的东西，而一个
**断掉的**链接根本解析不了：`fileExists` 会跟随链接、报告它不存在，归一化退回到它所在的目录，
于是它通过了一项正常的链接过不了的包含性检查。这一点在验证时真的被测出来了（一开始是被接受
的），修法是两个方向都不搬链接。代价接近于零：没有人粘贴一个符号链接是指望它指向的东西之后
才出现。一个边角：复制的是一个链接时，它会被跳过，其余的东西照常过去，你会看到「部分没搬」
那句提示——不会因为一个链接把整次粘贴（连同文字）都作废。另外，整个文件夹搬过去时是按「一项」
检查的，文件夹**里面**的链接会作为链接一起过去——它指向的东西，Agent 账号依旧读不到。

**Agent 那边没有新工具，也不会加。** 这个桥接由人在窗口里的按键触发，而一个人的剪贴板不是
Agent 可以按需读取的东西。MCP 里的 `clipboard_read` / `clipboard_write` 仍然是 0.1.82 那个
只针对 Agent 账号自己、只处理文字的 API；Agent 要粘贴，仍然是 `key cmd+v`，粘的是它自己
放上去的内容。

**账号页多了一行「剪贴板粘贴」。** 它读 Worker 报的静态能力，显示「文字和文件」/「仅文字」/
「当前 Worker 不支持」/「未知（Worker 未运行）」四种之一——「功能坏了」和「Worker 是旧的」
必须在你按下那个键之前就能分开。休眠中的账号显示「未知」而不是「不支持」：没人问过就不能
当成否定回答。

**验证边界。** 两个方向都在真实的 Agent 会话里、对着真实的 Worker、在 unix socket 上量过：
文字（含中文和 emoji）、单个文件、整个文件夹都读回来过，1 MiB 与 32 项两条边界都试过，
越界的文字回答 `BAD_REQUEST`、40 个文件回答 `{files: 32, truncated: true}`，符号链接的
修复是量出问题之后才修的。三种「不搬」的判断（文字过大、项数过多、只有图片或富文本）和
按键的识别规则由单元测试固定；完整的那一次手势——在一个真的桌面观看者窗口里真的按一次
⌘V，一直走到 Agent 应用真的粘出内容——**没有**在这次里端到端跑过：桥接两侧都量了，按键
那道接缝是单测和源码验证的，中间这一段（按键 → 桥接 → Worker → Agent 应用的粘贴）第一次
真实运行就是它的实机验收，和这个产品所有输入路径一样由你来当仪器。

验证见 validation §397。
