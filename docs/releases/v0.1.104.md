# AgentSpace 0.1.104

**更新后首次使用时,应用会像每次版本更新一样提示一次 Worker/助手版本对齐(本版未改动助手行为,仅版本号随版)——请照常允许。**

## 这一版改了什么

**排查结论:「正在监听」检测没有缺陷;一份把「监听者在账号之外」说清楚的新文案。**

- **排查(实测):端口 3425 拒绝映射是正确行为。** 主系统实测 `lsof`:监听 `127.0.0.1:3425` 的进程在**主系统**(主系统里的网关应用);子账号里的同名应用只是以客户端连过去(`127.0.0.1:52728 → 127.0.0.1:3425` ESTABLISHED)。macOS 所有账号共享同一套回环网络,所以这样的服务**现在就可以在主系统直接访问 `127.0.0.1:3425`,不需要、也不可能由端口映射代劳**——端口映射只服务于「子账号自己的进程监听的端口」。
- **改进:拒绝的话把话说全。** 此前输入这类端口只会看到「子账号此刻没有进程在监听 3425 端口」,容易让人以为检测出了问题。现在当该端口在本机回环上**有**进程应答、但不属于该账号时,App 和 CLI 都会明确说明:监听者在账号之外(主系统、其他账号或系统服务)、主系统已经可以直接访问、无需映射。端口在本机任何地方都无应答时,维持原来的提示不变。
- **列出子账号暴露的端口,两个现成入口**:账号页「端口映射」卡片里「正在监听」一排(点选即填入),以及 `agentspace ports <账号> list`。它们列出的就是该账号自己进程监听的全部 TCP 端口(以该账号身份运行 lsof,不含其他账号的)。

## 测试

新增 `notListeningRefinement` 纯函数(两条拒绝路径的升级判定,4 项单测)与新本地化句(两表齐全);全套 Swift 测试 **1074 项、0 失败**。真机实测:`map 3425` 答出新句子(监听者在账号外),`map 3426` 维持原句(全机无监听)。
