# AgentSpace 0.1.99

**更新后第一次使用时，请允许一次「重新安装助手…」（即 Worker 更新，可能需要一次管理员确认）。** 这是因为端口映射的探测跑在每个 Agent 账号自己的 Worker 里。除此之外不需要你做任何事：更新只替换 `/Applications/AgentSpace.app`，无需重新授权，也无需重新登录。

---

## 这一版带来了什么

**子账号里的本地 API，现在可以在主系统直接调用——断网也行。**

- **端口映射**：子账号（Agent 账号）会话里监听的服务，映射到 `127.0.0.1` 上一个**固定生成的端口**（45,000–46,999），主系统直接 `curl http://127.0.0.1:<生成的端口>` 即可，完全不需要网络。
- **账号页一键映射**：每个 Agent 的详情页新增「端口映射 / Port Map」卡片，列出该账号此刻在监听的端口和进程名，一键映射/取消。
- **CLI**：`agentspace ports <账号>` 查看监听与映射，`… map <端口>` / `… unmap <端口>` 写入映射。
- **归属校验，失败即拒绝**：所有账号共享同一内核网络栈，`127.0.0.1:3000` 说不出是谁的服务。转发器在**每一次连接**前都会问该账号自己的 Worker「这个端口现在还是你在监听吗」，答案为否（或 Worker 离线）就拒绝连接——绝不把你的调用转给别的账号。
- **映射由 App 提供**：AgentSpace 打开期间转发器常驻；关闭 App 即关闭所有生成端口（界面有说明）。

## 为什么生成的是端口，不是 IP

macOS 不允许普通进程绑定 `127.0.0.1` 以外的任何回环地址——实测 `bind()` 在 `127.0.0.2` 等任何 `127.x` 地址上都返回 errno 49（地址不可用），只有 `ifconfig lo0 alias`（需要 root）才能加上新地址。这正是上一版放弃内置隧道的同一条路。所以「生成一个地址」以**端口**的形式交付，且每个界面都如实说明。

## 顺手修好的三件事

- **远程 API 现在真的会被启动**：0.1.98 里 `agentspace api enable` 只写配置，没有任何进程真正监听。现在 App 打开期间会实时按配置启动/停止监听器，`agentspace api status` 改为**实测探测**并如实报告。
- **设置页显示的监听地址纠正**：默认绑定是 `127.0.0.1`（无网可用），旧界面却显示虚拟地址；无网模式下也不再要求先配置虚拟网络。
- **清掉指向已删除功能的提示**：`api status` 的「系统扩展」行、`api restart` 指向不存在的「Restart API」按钮、`network connect` 指向不存在的「连接」按钮，以及四处「隧道」措辞——内置隧道在 0.1.98 已删除，这些话如今要么消失要么如实说明。

## 协议与兼容

- Wire 方法新增 `ports.list`（只读，additive，协议版本仍为 1）；旧 Worker 会答 `METHOD_NOT_FOUND`，界面转为「请更新 Worker」提示而不是报错。
- 传输、注册表 JSON、既有 MCP 工具、权限模型、登录流程均不变。

已知边界：映射在 AgentSpace 打开期间生效；生成端口若被其他进程抢占，界面显示「端口被占用」，重新映射即可换一个。
