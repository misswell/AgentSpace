# 0.1.97 — 补上剪贴板那一次的实机验收：真的按一次 ⌘V，真的粘出来

**这一版不需要你做任何事。** 没有新功能，也没有 Worker 改动——`clipboard.push` /
`clipboard.pull` 和 `status` 里的 `clipboard` 块与 0.1.96 完全一致，所以**不需要**再按一次
「重新安装助手…」。0.1.96 装好之后保持原样即可。

**为什么还要发一版。** 0.1.96 的发布说明里写着一段诚实的话：桥接的两侧都量过了，按键那道
接缝也有单测，但**完整的那一次手势**——在一个真的窗口里真的按 ⌘V，一直走到 Agent 那边的
应用真的粘出内容——没有跑过，第一次真实运行就是它的验收。现在跑了，而且是通过的，这一版
就是把那次测量和它的测试固定下来。

**测的是什么。** 一个走**生产代码**而不是仿真的测试：真的 `NSWindow`、桌面观看者用的那个
真的 `RemoteKeyboardMonitor`、它调用的真的 `ClipboardBridgeHost`、一个通过
`NSApplication.sendEvent` 投递的真 ⌘V 按键事件（`addLocalMonitorForEvents` 就是在这一步被
执行的）、AgentUse 自己会话里一个真的 Worker（走真的 unix socket），以及观看者快通道不通时
用的那条真的 `SpaceService().input` 回退路径。

**结果。** 按键被转发而不是被吞掉；Agent 的剪贴板上确实有你的文字**和**那个文件，而且每个
路径都存在；Agent 那边的应用也把结果显示出来了。这里有一个细节值得写下来，因为它是**量**
出来的、不是猜的：同时带文字和文件的剪贴板，在 TextEdit 里被粘成了一个**文件附件**（它的
文档里是 U+FFFC，没有文字）——优先粘文件是那个应用的选择，不是桥接的缺陷；而只有文字的
剪贴板，随后就以文字出现在文档里，这才是「应用真的粘出来了」没有歧义的那一例。

**测试第一次跑就失败了，而且失败得对。** 这台机器上装着的 Worker 是 0.1.95，它的 `status`
里没有 `clipboard` 块，测试拒绝把这种情况当成能用——「字段不存在不等于 false」这条规则在
真机上自己验证了一次。

**我自己的一个缺陷，也写在这里。** 那个测试第一版的「备份/还原你的剪贴板」会丢掉读不出数据
的剪贴板类型，于是一个条目变成空组，还原空组等于什么都没还原——它让你当时复制的那张图片
丢了。现在这类条目整个丢掉而不是留个空壳，还原失败会**报出来**而不是咽下去，测试还会断言
你的剪贴板确实回来了。验证方式：先放一张已知的图片到剪贴板上，跑一遍测试，再看它还在不在。

**测试默认不跑**（要 `AGENTSPACE_LIVE_CLIPBOARD_TEST=1`）：它需要有一个可用且不在物理控制台上的
会话，而且它会往另一个桌面发按键。普通 `swift test` 里它是一条带原因的跳过，不是通过。

验证见 validation §397 的 row 1334。
