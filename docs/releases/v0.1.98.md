# AgentSpace 0.1.98

**这一版不需要你做任何事。** 更新只是替换 `/Applications/AgentSpace.app`，无需重新安装助手，也无需重新授权。

---

## 这一版带来了什么

**给 Agent 一套固定的虚拟地址，加一个 HTTP API。**

- **固定 IPv4**：自动从 `100.64.0.0/10`（其次 RFC 1918）随机选一个 `/24`，避开这台 Mac 已有的网络。枢纽 `.1`、主系统 `.2`、这台 Mac `.11`，地址持久化，重启不变。
- **冲突检测**：检查本机接口与路由表；读不到时报告「未验证」而不是「无冲突」。本机已占用的地址永远拒绝，没有覆盖开关。
- **精确路由**：每个节点只走自己的 `/32`，不是整个网段——家里正好用同段私有地址也不会被抢走。
- **事务式改址**：先预览再应用，保留上一版可回滚；离线节点会被点名，不会假装它们已迁移。
- **HTTP API**：Bearer 令牌（只存 SHA-256 摘要）带 `read` / `observe` / `control` 权限，令牌级与 Agent 级双重限流。Worker 离线返回 503，绝不回退到你的桌面。
- **设置页**：设置 → 虚拟网络，可编辑、可预览、可回滚。
- **CLI**：`agentspace network …`、`agentspace api …`、`agentspace api-token …`。
- **自托管 Hub**：`network/hub`，一次性注册令牌、按公钥幂等、固定地址分配、节点撤销。

## API 默认只监听 127.0.0.1

这是刻意的选择：回环地址在任何网络接口起来之前就存在，所以**断网、飞行模式、没有 Wi-Fi 时 API 依然可用**，而且永远不能被别的机器访问——对一个能操纵桌面的接口，这是正确的默认。

想从另一台机器访问，两种方式：

1. **用你已经在跑的虚拟网络**。这台 Mac 上 Tailscale 和 ZeroTier 都在运行，把 API 绑到它们的地址即可（`agentspace api enable --virtual` 或在设置页选虚拟地址）。固定 IP、加密、穿透都由它们提供。
2. **用你自己的 WireGuard**。`agentspace network status` 会打印精确的主机路由和产品生成的配置，`network/hub` 是自建枢纽。

## 这一版**没有**内置隧道

我们确实做出了一个 packet tunnel 系统扩展：签名、公证、并在你的授权下激活成功（`activated enabled`）。

但 macOS 26 拒绝让它保存配置——`NEVPNErrorDomain 5 permission denied`。我们试了所有组合：无授权、完整授权、加 `allow-vpn`、通过 LaunchServices 启动、从已公证的 app 内部发起，全部被拒；去掉 `allow-vpn` 后请求甚至静默挂起。Tailscale 是靠一个 root 守护进程绕过这条限制的。

**所以这个扩展被移除了，而不是带着「半可用」的状态发布。** 系统扩展列表里不再有 AgentSpace 的隧道。代价说清楚：这一版没有内置隧道。

## 还没做

- IPv6：只保存开关，未实现。
- 托管协调服务：Hub 需自建（见 `docs/network-hub-deployment.md`）。
- API 没有随登录自启的 LaunchAgent。
- 桌面流：截图是一次性 PNG，没有视频接口。
- `exec` 没有 HTTP 端点。

## 验证

`docs/validation.md` §398 与 §399 记录了全部实测：地址规划、冲突检测、Hub 分配与幂等、真实 `wireguard-go` 双向握手、API 的真实 socket 测试（含 Worker 离线必须 503、只绑定指定地址），以及系统扩展那条路为什么走不通。未验证的部分在同一处明确列出。
