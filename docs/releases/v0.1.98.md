# AgentSpace 0.1.98

**这一版要你做三件事**，都只需要一次：

1. **重新安装助手**。AgentSpace 的 bundle 标识改为 `com.misswell.AgentSpace`（原因见下），已安装的旧助手会拒绝新版 app。打开 AgentSpace，按提示点「重新安装助手…」，macOS 会要一次管理员密码。
2. **重新授权 app 的辅助功能与屏幕录制**。授权记录跟着 bundle 标识走，新版 app 会被当成新应用问一次。**Agent 账号自己的授权不受影响**（自动化跑在 Worker 里，Worker 没换标识）。
3. 如果你的机器上还留着 `AgentSpace Net POC`（0.1.98 之前的可行性验证包），在「系统设置 → 通用 → 登录项与扩展 → 网络扩展」里移除它。

更新本身仍然只在 app 内替换 `/Applications/AgentSpace.app`。

---

## 这一版带来了什么

**内置虚拟网络与远程 HTTP API。**

给这台 Mac 和驱动它的机器分配固定的虚拟 IPv4 地址，通过 WireGuard 加密隧道互通，然后用 HTTP API 远程控制指定的 Agent——不需要配置路由器，不需要公网 IP。

- **固定地址**：自动从 `100.64.0.0/10`（其次 RFC 1918）随机选一个 `/24`，避开本机已有网络。Hub `.1`、主系统 `.2`、这台 Mac `.11`。地址持久化，重启不变。
- **精确路由**：每个节点只走自己的 `/32`，不是整个网段——所以家里正好用同段私有地址也不会被抢走。
- **冲突检测**：检查本机接口与路由表；读不到时报告「未验证」而不是「无冲突」。本机已占用的地址永远拒绝，没有覆盖开关。
- **事务式改址**：先预览再应用，保留上一版可回滚；离线节点会被点名，不会假装它们已迁移。
- **HTTP API**：Bearer 令牌（只存 SHA-256 摘要）带 `read` / `observe` / `control` 权限，令牌级与 Agent 级双重限流。只监听虚拟地址或 `127.0.0.1`，**没有监听所有网卡的选项**。Worker 离线返回 503，绝不回退到你的桌面。
- **设置页**：设置 → 虚拟网络，可编辑、可预览、可回滚，并能安装/连接隧道。
- **CLI**：`agentspace network …`、`agentspace api …`、`agentspace api-token …`。
- **自托管 Hub**：`network/hub`，一次性注册令牌、按公钥幂等、固定地址分配、节点撤销。

## 为什么改了 bundle 标识

macOS 的系统扩展要求宿主 app 带 `com.apple.developer.system-extension.install`，而这个授权必须由描述文件授权——没有描述文件的 app 会在 `main` 之前被 `amfid` 直接杀掉（实测退出码 137，无任何输出）。

描述文件只能签给本团队拥有的 App ID，而 `com.agentspace.AgentSpace` 属于另一个 Apple 账号，无法创建。所以标识改为 `com.misswell.AgentSpace`。这就是上面第 1、2 条要做一次性处理的原因。

## 隧道需要你允许一次

虚拟网络由**系统扩展**承载——macOS 不允许 packet tunnel 用 app extension 做 Developer ID 分发。首次使用：

1. 设置 → 虚拟网络 → **安装隧道扩展**
2. 系统设置 → 通用 → 登录项与扩展 → **网络扩展** → 允许 **AgentSpace**
3. 设置 → 虚拟网络 → **连接**

**这一版的隧道是新的、还没在有真实流量的机器上跑过。** 扩展已签名、已公证、已被 macOS 识别（`com.misswell.AgentSpace.Tunnel`），但截至发版没有人点过那次「允许」，所以还没有一个数据包穿过它。它使用的 WireGuard 配置已用真实 `wireguard-go` 双向验证通过。请把第一次连接当作试用，而不是既成事实。

## 还没做

- IPv6：只保存开关，未实现。
- 托管协调服务：Hub 需要自建（见 `docs/network-hub-deployment.md`）。
- API 没有随登录自启的 LaunchAgent。
- 桌面流：截图是一次性 PNG，没有视频接口。
- `exec` 没有 HTTP 端点。

## 验证

`docs/validation.md` §398（含 addendum 行 1347–1353）记录了全部实测：签名、公证、系统扩展激活的四种失败形态、Hub 分配与幂等、真实 `wireguard-go` 双向握手、API 的真实 socket 测试（含 Worker 离线必须 503）。未验证的部分在同一处明确列出。
