# 0.1.39 — 产品行为没有变化，第一版由 GitHub Actions 自动发出来的包

**这一版没有任何产品改动。** 唯一变的是「发版这件事由谁来跑」：从现在起由
`.github/workflows/release.yml` 在 GitHub 的 macOS 26 runner 上签名、公证、发布，
不再依赖某台 Mac 的钥匙串。所以第一行就说明白，避免让人以为里面有新东西。

## 为什么发这一版

不是为了修 bug，也不是为了加功能，而是为了**验证新的发版链路真的能从头跑到尾**：
`0.1.38` 的代码是在本机手工发的，CI 那条路只跑过 dry run（不发布）。一个只在
dry run 里成功过的发版流程，不算被证明过。这一版的产物就是那条链路的证据。

## 你要做的事

**不用按第二下。** 「检查更新」即可 —— worker 的代码与 0.1.38 完全相同，所以
不需要「重新安装助手…」。装与不装，鼠标的行为一模一样。

（如果你已经装有 0.1.38 的 App 和 worker，这一版可以跳过不装。）

## 这一版验证了什么

- tag 触发、版本号一致性、release notes 必须存在 —— 都在打包前先检查，不一致
  就几秒钟内失败，不会白跑一遍测试
- Swift 测试 697 项、updater-e2e 19 项、MCP smoke 全通过（前三层闸门）
- Developer ID 签名、Apple 公证（App 与 DMG 两次提交）、staple、Gatekeeper 通过
- 发布后断言 `releases/latest` 返回新 tag **且** 带的是本次被测产物的 digest

## 这一版没有验证什么

- **第 4 层闸门（界面检查）没有在 CI 上跑**：它需要一台控制台会话加上
  Accessibility 授权，hosted runner 拿不到。涉及界面的发版仍然应该在本机跑一次
  `scripts/check-all.sh`。
- 与前几版一样，**没有在真机上真正看过画面**：这台机器没有连接的 agent 账号，
  控制台也处于锁屏状态。
