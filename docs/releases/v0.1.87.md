# 0.1.87 — 安装菜单先告诉你哪个客户端已经接好，MCP 多两个只读工具

更新 AgentSpace 到 0.1.87。**需要你做的事**：

1. 安装 0.1.87。Worker、helper 和 CLI 的协议没有变，已连接的账号和桌面不需要重新登录。这一版改的是 App 和随包的 MCP 服务（0.1.16 → 0.1.17）。
2. 重启你已经接了 AgentSpace 的那个 AI 客户端。它的 MCP 服务会多两个只读工具：`agentspace_doctor` / `agent_doctor` 和 `agentspace_diagnostics` / `agent_diagnostics`。**客户端配置不用重装**——24 个客户端的路径和格式一个都没动。
3. 想确认某个客户端接没接好，打开账号页「维护」卡片里的「把 MCP 安装到…」：已接好的排在最前并标「就绪」，跑着另一份安装的标「可运行，但不是本次安装」，条目坏了的标「需要修复」，配置文件存在但还没有 AgentSpace 条目的标「未配置」。

**菜单直接说状态。** 以前这个菜单只列 24 个名字，选之前看不出哪个已经接好。现在每个客户端后面的标签来自 `agentspace doctor` 用的同一个扫描器，而不是菜单自己另算一套：它读该客户端真实的配置文件，判断条目能不能启动本次安装的 MCP 服务。同组内按「就绪 → 别的安装 → 需要修复 → 已存在但未配置 → 没有配置文件」排序，同档保持原来的声明顺序；没有配置文件的那项不加后缀，菜单不至于变成一排状态噪音。状态随账号页已有的 3 秒轮询刷新，装完不用重开窗口。

**安装完当场给出扫描器的判词。** 写入后，App 把刚写下去的字节交给同一个扫描器判一遍再报告：`已验证：该条目会启动本次安装的 MCP 服务。`，或者 `但该条目不会启动本次安装的 MCP 服务：<原因>`。判断的是写入的内容本身，不是「写成功」这件事——和账号页说的状态是同一套话。原来的「已配置了 X，重启 X」和 `.agentspace.bak` 备份提示都保留。

**MCP 多了两个只读工具。** `agentspace_doctor`（别名 `agent_doctor`）运行 `agentspace doctor --json`，返回每项检查的名、状态、细节和修法。**失败检查是报告的一部分，不是工具错误**：doctor 以退出码 1 表示「有检查失败」时，调用方拿到的仍是完整 JSON 和修法，而不是一个 error——这条是 doctor 自己的 `ok:false` 与 CLI 失败信封撞车后专门改的。`agentspace_diagnostics`（别名 `agent_diagnostics`）返回同一个脱敏支持包文本，不写文件；`--out` 仍然只在 CLI 上存在。两个工具都标了 `readOnlyHint`，服务端说明也改了：遇到拒绝先调 `agent_doctor`，要报 bug 时调 `agent_diagnostics`。

**没有变的部分。** Worker、helper、协议、其余 29 对 MCP 工具、账号与桌面驱动、`SESSION_IS_CONSOLE` 拒绝路径都不变；没有新增任何绕过物理控制台的路径，也没有让 MCP 去驱动你的主会话。24 个客户端的配置路径与 schema 一个没动，已装好的客户端不需要重做。
