# 0.1.88 — 登录对话框里直接给「重新安装助手…」，修完自己接着登录

通过「检查更新」更新到 0.1.88 即可。**这一版只改 App 的登录对话框**：Worker、helper、CLI
和协议都没有变，已连接的账号与桌面不需要重新登录。

更新后如果「登录 / 解锁 Agent」说特权助手不可用，或者已安装的助手来自旧版本，**修复按钮就在
这个对话框里**：点「重新安装助手…」，允许一次 macOS 管理员授权。授权通过、助手用本版本的
二进制应答之后，刚才被挡住的登录会自动继续，不需要再点一次「打开 macOS 登录窗口」。授权被
拒绝或安装失败时，原因会显示在对话框里，按钮留着可以再按一次。

**以前是一句话，现在是一个按钮。** 登录前 App 必须让 root 助手确认目标账号的图形会话；助手
没应答、应答的是更新前留下的旧二进制、或者半小时里一直问不出结果，这三种失败此前都只说
「请在 AgentSpace 中安装或修复助手」或「去诊断里重装」——把一个人从正在做的事推到另一个
窗口。现在这三种失败都直接把「重新安装助手…」放在同一行动作里，文案也改成「请在下方重新
安装助手」。它跑的是「诊断 → 重新安装助手…」用的同一个等待完成的换装流程：先停掉旧守护
进程，再注册本应用内的新版本，并等新助手真的用当前构建应答；不是发出去就不管。

**失败留在原地说清楚。** macOS 的管理员授权被拒绝、或者换装后助手仍不答时，对话框会在
按钮上方显示助手自己的拒绝原因；如果原因是「在系统设置里等待批准」，那里就有「打开系统
设置」按钮。App 级弹窗不会盖在这张对话框上，也不会在关掉对话框后再补一遍同样的错误。

**没有变的部分。** 密码仍然只由 macOS 屏幕共享窗口处理，AgentSpace 不读取、不保存，也没有
任何密码参数、日志字段、注册表字段、助手操作或 agent RPC 新增。助手的操作清单与协议版本
没变，`SESSION_IS_CONSOLE` 的拒绝路径没变，也没有新增绕过物理控制台的路径。

验证证据见 validation §389（三种失败各自点亮修复按钮的源码断言、按钮执行的是等待完成的同一
换装、成功后才自动重试登录、拒绝在对话框内可见；层 1–3 的实跑数字见该节）。层 4 的 17 项
检查跑在本次树的测试包上，但它们不制造助手故障，因此**按钮的实时按下仍只有源码与单元测试
作证**——这一点照实记在那节。
