# 0.1.53 — 助手批准流程可视化：每一步都告诉你该怎么做，而不是卡死

**这次需要两步，而且第一步在系统设置里**：通过「检查更新」更新 App 之后，请按一次「重新安装助手…」——本回合的核心修复之一在 **helper** 里，不换 helper 不生效。macOS 会要求输入管理员密码。

## 背景：为什么「连接账号」会没有反应

macOS 会先把注册的 LaunchDaemon 扣在「等待批准」状态：只有系统设置 → 通用 → 登录项与扩展 → 「允许在后台」里把 AgentSpace 打开，helper 才会启动；在这个状态下，App 里的「安装助手」只会被 macOS 以 "Operation not permitted" 拒绝，而且系统**不会再弹提示**。0.1.52 及更早的界面对这三件事只给了一句静态文字：按钮点了没反应（连接按钮在 helper 不可用时本来就禁用）、报错看不懂、批准完状态也不刷新。本回合把整条链路变成界面上的可视化引导。

## 改了什么

- **向导的助手卡片新增「等待批准」专属状态**（代码 `HELPER_NEEDS_APPROVAL`）：说明 helper 已注册、批准是只有用户本人能做的安全决定，并给出两个按钮——「打开系统设置」（直接打开登录项面板）和「重新检查」。
- **等待批准期间自动轮询**：卡片每 3 秒重读一次 helper 状态，你在系统设置里一批准，回到向导时卡片自动变绿、「连接账号」自动可用——不用关闭重开向导。
- **注册失败不再显示裸系统报错**：凡是 macOS 因等待批准而拒绝注册（`SMAppServiceErrorDomain` 错误 1，"Operation not permitted"），横幅改为说明真实原因，并附「打开系统设置」按钮（`HelperRegistrationGuidance`，Core 可单测）。
- **所有「助手不可用」状态都补了「重新检查」按钮**：不再有任何需要碰运气重开界面才能恢复的死路。
- **Doctor 同样接入**：等待批准时给出「打开系统设置 / 重新检查」按钮，而不是只会建议重装。
- **修复 CLI/doctor 被助手拒绝的潜伏缺陷**：helper 的调用方签名要求只写了 app 和 helper 两个标识，而 CLI 是独立 Mach-O、标识是 `com.agentspace.AgentSpace.CLI`——所以 CLI 的 doctor 在 helper 正常应答时也一直报「无响应」（本机实测：`log stream` 抓到逐字拒绝日志）。现在三个标识都在要求里；该修复在 helper 内，需要「重新安装助手…」落地。
- **补翻译**：登录项修复文案的简体中文此前缺翻译（界面上中英混排的那句），已补上。

## 兼容性

协议未动，`protocolVersion` 仍为 1；注册表与 wire 方法无变化；helper 的调用方要求只**放宽了本就应当被接受的一个签名标识**（自家 CLI），不涉及其他组件。验证记录见 `docs/validation.md` §345。
