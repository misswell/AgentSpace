# 0.1.83 — Agent 连接：客户端能不能启动 MCP 服务，现在四处都能看到

更新 AgentSpace 到 0.1.83。**如果你在 0.1.82 之后已经对正在用的客户端重新执行过「Install MCP Into…」或 `agentspace integrate <client> --install` 并重启了它，这次无需任何操作。** 如果没有——尤其是 AI 说过「没有可用的 AgentSpace」——请执行 `agentspace integrate <你的客户端> --install`（claude、codex、opencode、zcode、kimi、mimo），然后重启那个客户端。本次只改 App 和 CLI 的诊断与显示，Worker 没有新能力；更新后应用会按既有流程把 Worker 版本核对到 0.1.83。

**为什么会有这个版本。** 上一条反馈：AgentSpace 窗口里账号「就绪、Worker 运行中、接受输入 是」，而旁边的 AI 客户端说「当前环境没有可用的 AgentSpace」，并提议改在人的桌面里执行。两边都没说谎——桌面确实是可用的 Agent 桌面，而客户端一个 `agentspace_*` 工具都没有，因为它自己配置里的启动命令起不来：旧版本生成的配置仍在运行 `npx -y @agentspace/mcp`，而这个包从未发布到 npm。0.1.82 起 App 自带 MCP 服务，但先于它写下的配置不会自己变。这个版本让「客户端侧」这个事实和「桌面侧」一样可见、可修。

**`agentspace doctor` 新增第 13 项「Agent connections」。** 扫描六种客户端（Claude Code、Codex、OpenCode、ZCode、Kimi、MiMo）各自的配置文件，逐项给出：正常（能启动本次安装的 MCP 服务）／失效（连同这一条修复命令）；一台客户端都没配置时提示该装哪一个；逐个失效客户端列出它配置里的命令为什么起不来。只读，不写任何文件。在这台机器上它就是发现本次问题的工具：Codex 与 ZCode 的旧配置被指名，执行给到的命令后两者都恢复。

**账号详情页新增「Agent 连接」一行**，与「就绪」并列：绿色列出可用的客户端；橙色时附上修复命令；多个客户端谁失效就点名谁。「就绪」描述桌面，这一行描述客户端——它们回答的是两个问题，放在一起才不会被误读。

**修复只动自己生成的条目。** 精确匹配的旧 Codex 配置会被迁移到 App 自带的启动器；自定义条目原样保留并被指出；JSON 只合并不覆盖其他服务器；改前备份（`*.agentspace.bak`）。密码、授权、管理员批准仍由人在 macOS 里完成，这一版本没有任何一步替人做决定。

验证证据见 validation §384（含本机实测、13 个分类器单元测试与四层门禁记录；层 4 的 GUI 检查因该 Agent 会话的 AX 状态无结论，已按 §381 先例如实记录）。
