# 0.1.79 — 桌面观看者的顶栏和三个窗口按钮合成一行

更新 AgentSpace 到 0.1.79 就行：**这一次只改 App 本身**，在应用里点「检查更新」装完即生效，不动 Worker、不动特权助手，也不需要管理员授权。然后打开某个账号的桌面观看者，顶栏应该是一行：红绿灯（关闭／最小化／缩放）和右边那一排控件（重连、暂停、画质、帧率、鼠标捕获、截图、ⓘ、✕）在同一条带上。

**为什么上一版没做到**

0.1.63 那次（§361）就写了「控制条就是标题栏」，代码也确实给窗口加了 `.fullSizeContentView`、把标题栏设成透明、标题不画——但窗口里从来不是这样。原因是 AppKit 的一条行为，源码里看不见：SwiftUI 内容装进 `NSHostingView` 时，标题栏的高度会作为**顶部安全区**交给 SwiftUI，于是整条控件条被往下推了一个标题栏的距离，红绿灯独占一行，控件条成了第二行。那一版的记录里其实写了「合并后的样子待肉眼确认」，这次你的截图把这句话结清了：没合并。

这一版就是释放那个顶部安全区（`ignoresSafeArea(.container, edges: .top)`），一行代码的事，但先测了三件事再动手——都在子账号自己的会话里测，没有占用你的屏幕：

- **控件画进标题栏那条带里，还收得到点击吗？** 收得到。用一个和观看者窗口同样式的一次性探针窗口，控件条顶边落在窗口顶边（SwiftUI 报 `(0, 0, 700, 28)`，标题栏实测 32 pt），`agentspace click` 打在那条带里的按钮上，按钮自己的动作日志回来了。
- **那条带的空白处还能拖动窗口吗？** 能。拖控件条右半的空白（1010,192 → 1110,292），两张截图里控件条的顶边从 178 走到 278、左边从 610 走到 710，正好是拖动的位移。
- **那个「标准做法」行不行？** 不行，而且会撞车。`NSTitlebarAccessoryViewController` 配 `.leading` 是往标题栏放视图的正规 API，但它的宿主视图落在 `(18, 5, 120, 22)`——压在红绿灯上面，截图里缩放按钮的位置被它盖住了。它是给工具栏项目用的，不是一条通宽的控件条。

**这一版顺手补了「说了没做」的那类错**

§361 的错不在于没做，在于用代码和构建通过当作界面已经成立。所以这一版让窗口自己说：桌面观看者每次开窗口会往日志里写一行（subsystem `com.agentspace.app`，category `viewer-chrome`），内容大致是

```
control strip occupies 372..400 of a 400 pt window; title bar is 32 pt, so the strip starts 0 pt below the top edge — one row with the window buttons
```

结尾是 `one row with the window buttons` 就是一行；如果写成 `a second row below them`，说明这次没合上，那行日志里的数字就是问题所在。这个数字是控件条自己的视图报出来的，不是从「窗口高减去画面高」推出来的——后者在两种情况下算出来都是「控件条高度」，等于什么都没测。

**这一版没有解决什么**

控件条本身约 28 pt 高，红绿灯是 AppKit 在 32 pt 的标题栏里垂直居中的——两者差 4 pt 的观感、以及 ⓘ 详情气泡从一条带里的控件弹出后箭头指得准不准，这两件都要真机上看一眼才能定。日志那行能给出前者的数字，后者只能看。第 4 层门禁（真机 UI 检查）这一版仍然没跑：`gui-verify.sh` 会关掉本机这个用户的所有 AgentSpace 实例并在你的屏幕上开窗口，而会话内的替身跑的是空注册表，里面没有账号，也就开不出桌面观看者。

**安全边界**

本版没有新增任何密码入口、密码日志字段、注册表字段、特权助手操作或 agent RPC；`HelperProtocol` 的操作清单、协议方法名和 `protocolVersion` 都没有动。改的只有 App 的窗口布局，加的是 App 自己的一行诊断日志。
