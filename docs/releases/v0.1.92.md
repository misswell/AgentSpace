# 0.1.92 — 「记住密码」这次真的会记住

**直接更新 App 即可，这次改动在 App 里。** Worker、CLI、特权助手和 wire 协议都没有
行为变化；正在运行的 Worker 会像往常一样被 App 换成同版本。更新后第一次用「登录 / 解锁
Agent」前，先按一次面板上的「重新安装助手…」对齐版本——和 0.1.91 一样，这次版本号又变了，
它只是对齐，不影响下面的行为。

**为什么勾了也没用。** macOS 把屏幕共享的密码存成 `127.0.0.1:<端口>` 这一条键（登录
钥匙串里 `ptcl = "vnc "`，每次连接保存一条独立记录）。AgentSpace 每次登录都在 127.0.0.1
上开一个随机端口的临时中继，于是每次都是新键，永远命中不了旧记录。今天在钥匙串里能看到
四条旧记录，端口各不相同（65031、51105、62713、62754）——这正是你勾了「记住密码」却每次
还要输入的原因。

**现在端口跟着账号走。** 中继端口从账号的 UUID 推导，固定在该账号自己的端口上（纯函数
计算，不写注册表、不落盘，同一账号跨启动不变）。这样 macOS 的「记住密码」终于有一个稳定
的键可以命中。端口被别的本地进程占用时会退回随机端口，登录照常，只是那一次要再输入一遍；
日志会写明 `sign-in relay fell back to port …`。

**要你做一次：更新后第一次登录时重新勾选「记住密码」。** 之前那几条记录按旧端口保存，
不会匹配新端口；勾这一次之后，后续登录会由 macOS 自动带上密码。AgentSpace 仍然不读、
不存密码——「记住密码」是 Apple 窗口里的复选框，凭据在 macOS 的登录钥匙串里。

**没有改的：** 登录仍要经过 Apple 的屏幕共享窗口（认证发生在那里；0.1.91 起连接成功后
窗口会自动关闭）；「用屏幕共享打开该桌面」和授权向导仍保留窗口；关窗不会锁桌面（Worker
安装期间该账号的密码延迟固定为「永不」，validation §376）。如果更新并重新勾选之后仍然
每次提示输入密码，把当时的窗口截图和 `Export Diagnostics` 的日志发我，那就还有第二个
键在变。

验证见 validation §393：端口推导有固定值测试（含一条真实账号 UUID 的钉住值），空闲端口
会被采用，被占用时会回退且登录不失败，控制器确实请求账号端口并在回退时写日志。层 4 不会
真的登录，所以「第二次自动带上密码」仍要等一次真实登录来验证，这一点照实记在该节。
