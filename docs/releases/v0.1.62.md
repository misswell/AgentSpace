# 0.1.62 — 暂停不再谎报「正在抓取」；接管隐藏鼠标的光标修复

**这次 App 和 Worker 都有改动：先「检查更新」，再按一次「重新安装助手…」，两步都做完才是完整体验。**（只更新 App 时，暂停界面修复即生效；接管隐藏鼠标真正隐藏远端光标的部分在 Worker 里。）

你报告：点 ⏸ 暂停后，窗口显示「正在抓取 Agent 的桌面…」转圈——状态错误。原因：暂停时画面流已真实停止，但界面只有一个「流在」和「流不在」两种暗态，后者一律显示「正在抓取…」——对一个被你主动暂停的窗口，这句话是谎报（这也是首开竞态修复让它显眼的老毛病）。

- **暂停现在有自己的覆盖层**：「画面已暂停——画面因你按下暂停而停止。点击恢复实时」，点窗口任意处或工具栏 ▶ 都恢复。
- **暂停期间不吞键盘**：与休眠同一规则——没有画面可看时，按键不得经 RPC 后备盲打进 Agent 会话。
- 其余所有启动路径（重连、画质变更、自动补启动）都会正确清掉暂停覆盖层，三个暗态（休眠／暂停／抓取中）互斥。

- **修复「接管隐藏鼠标未实现」**：你测试后报告画面里的鼠标依然显示——这条链路从第一次上线起就没真正工作过：桌面查看器发送「关闭画面内嵌光标」的闭包捕获了一个还是 nil 的客户端引用（永远没发出去）；Worker 侧的开关又搭在「改帧率」路径上，帧率不变就提前返回，`SCStream.updateConfiguration` 从未执行，画面一直把光标画进视频里。两处都已修复；「接管隐藏鼠标」现在会真正隐藏画面里的光标、只画 Agent 会话发布的光标；「接管」（保留你自己的光标）也不会再叠加第二个光标。

验证记录见 `docs/validation.md` §358 与 §359。
