# 0.1.58 — 设置按钮修好：按下真的打开设置窗口

**这次只改了 App：通过「检查更新」更新即可，不需要「重新安装助手…」。**

0.1.56 在主窗口工具栏右上角加的设置入口点不开——你实测点了没反应。原因：那一版走的是 macOS 13 时代的 `showSettingsWindow:` 选择器，而新 SDK 的 Settings 场景已经不再连接这个旧 action，兜底的旧拼写同样无效，所以点击被无声吞掉。更难堪的是它通过了当时所有的门槛：session 侧检查自己是用 ⌘, 菜单打开设置的，齿轮死没死根本不在被测范围里。

- **改用 `SettingsLink`（macOS 14+ 的一等入口）**，设置场景自己认得它；macOS 13 构建下限保留旧选择器。部署目标没动。
- **把齿轮变成被测对象**。session 侧 GUI 检查新增一条：按下工具栏齿轮、断言设置窗口真的出现（旧路径 ⌘, 只作兜底，走兜底即判 FAIL）。本轮候选包上 **14/14 通过**——齿轮按下后设置窗口在 Agent 会话里真实出现，后续的设置页检查（滑块、质量档、更新面板）也全部经由齿轮打开的窗口读出。
- 控制台侧的孪生门槛本轮未加同款检查：它需要占用你的屏幕一两次来开发调试，本轮你正在用机器。已按 §325 row 885 的先例如实记录，下次有控制台空档再补。

验证记录见 `docs/validation.md` §350。
