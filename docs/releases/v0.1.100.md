# AgentSpace 0.1.100

**更新后会像以往一样提示一次「重新安装助手…」（助手对齐，可能需要管理员确认）——这是每个助手变更版本的既有一次性流程，请允许。** 除此之外：**「固定地址」功能默认关闭**；不打开它，这个版本不会为此多要任何授权、不做任何额外的事。已连接的账号、端口映射、API 全部照旧。

---

## 这一版带来了什么

**端口映射现在有完整的图形界面，端口可以自己指定，而且（可选）每个账号可以有一个自己的 IP。**

- **可视化界面**：Agent 详情页的「端口映射」卡片重新设计——
  - **添加映射**：左边填子账号里服务监听的端口（下方会直接列出该账号**此刻正在监听**的端口，点一下即填入），右边填主系统要用的端口（**留空自动生成**），点「添加」即生效。比如 `8080 → 28080`。
  - **映射列表**：每条显示 `8080 → 127.0.0.1:28080` 和实时状态，可单独移除。
- **手动指定端口**：CLI 同样支持 `agentspace ports <账号> map 8080 28080`。自选端口须 ≥1024、避开自动生成段（45000–46999）、且不能与服务自身端口相同；一个外部端口只属于一条映射。
- **账号固定地址（默认关闭）**：账号页新增开关「给该账号一个固定地址」。打开后，**已安装的特权助手**会在回环网卡上放一个只属于该账号的 `127.100.x.y`，此后每条映射还会以**原端口号**在该地址上应答——`http://127.100.x.y:8080` 就是这个账号的 8080。关闭或断开账号即自动移除。开启本身**不需要新的管理员授权**（助手已装好）；若已安装的助手早于 0.1.100，应用会按惯例提示一次更新。
  - 这是通过现有 root 助手**封闭类型化清单**新增的一个最小操作实现的：它只接受一个 IPv4 地址、只接受 127.100.0.0/16 这一个网段、底层是 ioctl 而非 shell。应用从不相信操作回执——以 `getifaddrs` 读到的真实网卡状态为准，界面上显示的就是网卡上真实存在的。

## 安全行为（与 0.1.99 相同，未放松）

所有账号共享同一内核网络栈，`127.0.0.1:8080` 本身说不出是谁的服务——转发器在**每一次连接**前都会向该账号自己的 Worker 验证端口归属，无证据即拒绝；固定地址上的监听走同一道门。

## 协议与兼容

- 助手协议新增 `addLoopbackAlias` / `removeLoopbackAlias`（additive）；Worker 与 wire 协议**无变化**。
- 注册表 JSON、MCP 工具、权限模型、登录流程均不变。

已知边界：固定地址功能里的别名 ioctl 在本机尚无 root 环境下的实测记录（安装 0.1.100 助手需要 GUI 管理员确认）；设计上以网卡实测状态为准，若操作未生效界面会如实显示「未生效」及原因。
