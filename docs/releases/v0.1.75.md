# 0.1.75 — 登录等待会说明它在等什么，也不会再在你解锁前判失败

请更新 AgentSpace 到 0.1.75，并允许它接着更新 Worker（可能需要一次 macOS 管理员授权）。这一版改动同时在 App 和 Worker 两侧，只更新一边只能拿到一半。

**这一版做了什么**

- **登录窗口现在说清在等什么。** 之前从「macOS 还没把会话交出来」到「会话和 Worker 都好了、只差你在锁屏上解锁」这四种完全不同的状态，都显示同一句「正在等待 Agent 桌面…」。2026-10-09 实测：Agent 桌面从 09:52 起就一直锁着，Worker 上线之后又锁了 5 分 12 秒才被人解锁，而这段时间里窗口只说了那一句——它既可能是「还没登录」，也可能是「已经登录，只差你解锁」，而事实是后者。现在窗口会直接说「已登录。Agent 桌面仍处于锁定状态——请在系统窗口解锁该账号」，或者「正在启动 Agent Worker…」，或者「正在等待 macOS 完成 Agent 账号登录…」。
- **一旦 macOS 交出了桌面会话，等待不再有时间上限。** 原来的 10 分钟硬超时不分情况：解锁这件事只有人自己能做，多久做完不由 AgentSpace 决定，而如果人在 10 分钟内没能解锁，一次还在正常推进的登录就会被报成失败。现在时间上限只用于「始终没有出现会话」——那说明系统窗口被放弃了，继续等才是真的没有意义。
- **等待的原因会记一行日志**（`log show --predicate 'subsystem == "com.agentspace.app" AND category == "login"'`），只在原因变化时记，所以一次九分钟的等待是一行，而不是两百行。
- **修好上一版诊断日志里的两处失真。** `CGSSessionScreenLockedTime` 是绝对时间戳而不是秒数，之前被渲染成 `lockedFor=1791510767s`（相当于「已经锁了 57 年」），现在渲染成 `lockedAt=2026-10-09T09:52:47`；`askForPassword=` 这个字段被产品自己的脱敏器改写成了 `<redacted>`（它要挡的正是 `password=<值>`，这个规则对其它每一行日志都是对的），现在这个诊断字段换了个不会被吞掉的名字 `unlockNeedsPasscode=`，并且有一条测试保证整行日志原样抵达日志系统。

**这一版没有解决什么**

关闭屏幕共享登录窗口的那一刻，macOS 仍会立刻锁一次桌面——那是 Apple 的 `ScreensharingAgent` 在最后一个观看者离开时直接请求 loginwindow 上锁，任何屏保设置都挡不住它。0.1.74 已经移除了「闲置 20 分钟自动锁」这一类；断开这一类的做法仍然是点桌面里的「登录 / 解锁 Agent」，只是这一次窗口会告诉你它在等你做什么。

**安全边界**

本版没有新增任何密码入口、密码日志字段、注册表字段、特权助手操作或 agent RPC。解锁桌面这件事依旧只能由人在 macOS 自己的窗口里完成；`askForPassword` 仍然只读不写（`LockEvidenceTests.testAskForPasswordIsOnlyEverRead`），而且它是否被要求，现在能从日志里读出来——这一项只改变可读性，不改变任何写入行为。

## 修正（0.1.76，2026-10-09）

上面第二句「**一旦 macOS 交出了桌面会话，等待不再有时间上限**」写过头了，0.1.76 已纠正。它对「人在锁屏前磨蹭」是对的，但同一条规则把「会话有了、Worker 却始终起不来」也放成了永不结束——那一种只有 AgentSpace 自己在等自己的活，应该给结论而不是空转。现在时钟按状态计时，只有「桌面还锁着」是开放式的。

同一段里「一次九分钟的等待是一行」是随手举的例子，不是实测时长。实测的是锁证据那两行：最后一次读到桌面仍锁着是 **11:39:41**，解锁那一条边记于 **11:44:53**——中间 **5 分 12 秒**，窗口只说了那一句「正在等待 Agent 桌面…」（validation §377 row 1154）。

## 修正（0.1.77，2026-10-10）

上面第三句「等待的原因会记一行日志」附的那条命令，在实机上读不到任何东西。0.1.75/0.1.76 记这一行用的是 info 级，而这台 Mac 的登录窗口只有那条 error 级的「sign-in gave up after 10 minutes…」进了日志——同一个进程、同一个 subsystem、同一个 category，加不加 `--info` 都读不到 info 那行（同一个 subsystem 里 root 助手和 Worker 的 info/default 级都读得到）。0.1.77 把这行降到 default 级，命令也就按上面写的那样直接可用（validation §378 row 1167）。

更要紧的一条修正：这一段假设「登录其实成功了，只是窗口没解释清楚」。实测不是这样——助手判断图形会话的方式在这台 macOS 上从来就没有成立过，所以登录从来没有完成过。见 0.1.77 的说明与 validation §378 row 1162。
