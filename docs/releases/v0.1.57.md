# 0.1.57 — App 融合窗口跟手：把每个悬停包上的隐藏开销拆掉

**这次 App 和 Worker 都有改动：先「检查更新」，再按一次「重新安装助手…」，两步都做完才是完整体验。**

外部报告的现象是「系统窗口模式流畅，App 融合模式卡」。逐包对照两条路径后，差异不在显示管线——融合代理本来就是 `SCWindow` 窗口级捕获 + 共享内存脏矩形 + Metal 直渲（CAMetalLayer），与桌面查看器同一条路。差异在**输入的 worker 侧账目**和**速率策略**，全部在本轮拆掉：

- **悬停不再逐包激活远端窗口（需要「重新安装助手…」）。** 快速通道此前对每个转发的悬停/滚动包都做 `CGWindowListCopyWindowInfo` 全量枚举（每包最多两次）+ `NSRunningApplication.activate` + AX raise——以指针速率串行排队，正好压在交互的时候。而它镜像的 RPC 路径对悬停**从不**这么做的理由白纸黑字：光标划过代理窗口不应改变 Agent 正在工作的应用。现在两条路径语义一致：悬停零账目；点击仍即点即解析（绝不落旧帧）；滚动激活按 0.25 秒节流。
- **非 key 代理窗口不再硬 5 FPS。** 之前排在后面的代理无论内容动不动都只有 5 FPS；现在同样的活动阶梯、15 FPS 封顶——闲时仍是 5，内容在动或光标在工作时升到 15，手势仍按阶梯到 60。
- **按下瞬间提帧。** 融合代理此前要等拖动越过 3pt 阈值才把流提到 60；现在按钮按下的那一刻就提（桌面路径的 raw 模式一直如此）。
- **代理窗口缩放不再连着重开流。** 本地布局不再重算采集请求（§348 给桌面查看器的同一修法）；远端窗口自身尺寸变化仍会带来一次真实的源变化重连，这是绕不开的，但从「拖一次重连两次」变成一次。

方案里其余条目（窗口级捕获、IOSurface→Metal、脏矩形、自适应刷新、事件合并、性能 HUD、输入路由、线程模型）**已经是现状**——0.1.38/0.1.48 起逐步建成，本轮逐条对照记录在 `docs/validation.md` §349。隐藏鼠标接管在融合代理的稳态与桌面一致（Auto 模式）。

验证记录见 `docs/validation.md` §349。真实手感（尤其是多代理并发时的跟手度）仍欠本人确认（§349 如实标注）。
