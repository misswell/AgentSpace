# 0.1.78 — 关闭屏幕共享窗口不再把子账号桌面踢回锁屏

请更新 AgentSpace 到 0.1.78，**并在更新后允许它重新安装 Worker**（会要一次 macOS 管理员授权）。这一版的策略住在每台账号自己的 Worker 里，而 App 内更新只替换 `/Applications/AgentSpace.app`：只升 App、Worker 还是旧的，它就仍然只压住屏保、压不住断开——关窗口照样锁屏。允许重装之后，请再点一次「登录 / 解锁 Agent」把桌面登录起来（这最后一次仍然需要你自己输入子账号密码），此后关掉屏幕共享窗口，桌面就留在原地。

**这一版做了什么**

- **找到了那把门，并且把它关上了。** 上一版实测到的链条是这样的：你关闭屏幕共享窗口的那一秒，Apple 的 `ScreensharingAgent` 先问子账号的 loginwindow 一句 `SACScreenLockEnabled:`，loginwindow 回答 `1`，它才接着调用 `SACLockScreenImmediate:` 把桌面锁上（2026-10-10 09:56:11.986→.987，四行日志依次是 Enter／`returning:1`／`isEnabled = 1`／`SACLockScreenImmediate:271: enter`）。也就是说这次锁屏**不是**拦不住，而是被一个可以回答「不」的问题放行的。loginwindow 自己的代码里写着这个答案怎么算：它取该账号「上锁后多久要求输入密码」的数值，只要这个数值等于 `INT_MAX`，就走它自己那条日志 `Lock on, but int_max, setting to NO`——于是回答 0，`SACLockScreenImmediate:` 根本不会被调用。现在 Worker 在装着的时候把子账号自己的这个数值压到 `2147483647`，连同原来的屏保间隔（`idleTime=0`）一起。
- **上一版的登录确实好了，这一版接住它后面的那一步。** 0.1.77 的判断在实机上跑通了：`sessionInfo gui/503 → exit 0 bytes=109127 domain=graphical` 连答七次，09:55:21 的日志是「sign-in is complete: the agent desktop is ready」。51 秒后你关掉窗口，桌面又被锁回去——这次失败的原因和登录无关，纯粹是那把门。
- **两个值都是先记录、后写入，Worker 停下就还原。** 记录文件里每个键存自己的原值，只有真的被改过的键才有一条；停掉 Worker、或者在 AgentSpace 里断开这个账号，两个键都会回到你原来的状态（原来是「没有这个键」就删掉，不是替它编一个值）。旧的记录格式（0.1.74–0.1.77 只有一个键的那种）也照样能还原——升级时接手的 Worker 看到屏保已经被压住就不会重写它，能读回旧格式才不至于把这个账号永远留在压住的状态。
- **失败会被说出来。** Worker 启动时那行日志现在写的是两个键各自从什么压成了什么（`the account will not lock itself: idleTime 1200→0, askForPasswordDelay unset→2147483647`）；写不进去时是 `the account can still lock itself: could not write …`，而不是安静地假装成功。锁屏证据那行里的 `passcodeDelay=` 就是这次到底压住没压住的读数。

**这一版的代价，写在这里而不是藏在日志里**

Worker 装着的时候，那个子账号的锁屏**不再要求输入密码**。这是「关掉窗口桌面还在」唯一的那把门，也是它的价格：任何能进入这个子账号会话的人，越过它的锁屏不需要密码。边界是这样的：只有 AgentSpace 管理的账号被改动，你主账号自己的这些设置一个字节都不动（本版实测过这条边界：10:13:05 主账号按系统默认的 1200 秒上了屏保，被压过 `idleTime` 的子账号整上午没有一次闲置锁屏）；这是该账号自己的每用户偏好，由 Worker 以该用户身份在它自己的会话里写入，不需要 root、不需要助手、不涉及任何密码；停掉 Worker 或断开账号即还原。这个取舍是按你在 2026-10-10 的要求做的——「关闭窗口不退出子账号桌面啊，否则我登录解锁干什么」。如果你要的是相反的取舍（保留密码要求，接受每次关窗口都要重新解锁），说一声，这一半是可以单独退回去的。

**这一版没有解决什么**

`SACScreenLockEnabled:` 的答案由那个数值算出来，这一步是从 loginwindow 自己的机器码和字符串里读出来的，不是 Apple 文档承诺的行为；如果某台 Mac（比如被 MDM 托管的账号）不让这个偏好生效，断开仍然会锁屏。这种情况下 0.1.78 会把它写在日志里（`passcodeDelay=` 那一行），恢复路径也还在：桌面观看者的锁屏覆盖层上有「登录 / 解锁 Agent」，不需要你去找别的窗口。另外，第一次把子账号桌面登录起来这件事仍然只能由人来做——SecurityAgent 不接受注入的按键，而 AgentSpace 永远不持有你的密码。

**安全边界**

本版没有新增任何密码入口、密码日志字段、注册表字段、特权助手操作或 agent RPC，`HelperProtocol` 的操作清单没有变，协议方法与 `protocolVersion` 也没有动。写入的键被测试钉死为两个：`askForPassword`（决定锁屏到底要不要密码的那个开关）仍然只读不写，而且检查它的测试现在匹配的是带引号的字面量，免得合法的间隔键误报、真正的开关被某处新写的调用点加进去。
