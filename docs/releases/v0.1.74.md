# 0.1.74 — Agent 桌面不再被闲置锁屏打断，锁定时这一屏就能重新登录

请更新 AgentSpace 到 0.1.74，并允许它接着更新 Worker（可能需要一次 macOS 管理员授权）。更新完成后请确认 Agent 卡片上的 Worker 版本已是 0.1.74：只有新版 Worker 会替你管理子账号的屏保设置。

**这一版做了什么**

- 主账号登录子账号之后，桌面在大约 20 分钟整机无输入后被 macOS 锁掉、Agent 再也无法操作——这一类「闲置锁」现在从触发点上被移除：Worker 会用**子账号自己的**设置把屏保启动设为永不（`idleTime=0`），并且先记录原值，停止或断开账号时自动还原。写这个设置的是子账号会话里的 Worker 进程本身，不需要 root、不需要特权助手、也不需要密码。
- 桌面处于锁定状态时，画面里不再只是叫你去别处找按钮：桌面窗口内直接提供「登录 / 解锁 Agent」，解锁后本画面自动恢复。文案也不再武断地猜原因，而是说明两种可能。

**这一版没有解决什么**

关闭屏幕共享登录窗口的那一刻，macOS 仍会立刻锁一次桌面。那是 Apple 的 `ScreensharingAgent` 在最后一个观看者离开时直接请求 loginwindow 上锁（`SACLockScreenImmediate:`），不是屏保计时器，因此任何屏保设置都挡不住它。发生时的做法就是点上面那个按钮，重新用 macOS 的屏幕共享登录一次——AgentSpace 不读取、不保存、也不会代你输入密码。

为了把这两类锁分清楚，新版 Worker 会在锁状态每次翻转时记一行 `lock evidence:`：已锁多久、是否有进程持有 secure input、这个会话在不在物理 console，以及该账号自己的 `idleTime` / `askForPassword` 当前值。如果哪次锁定发生时 `idleTime=0` 已经在位，那就是上面这一类，而不是屏保。

**安全边界**

本版没有新增任何密码入口、密码日志字段、注册表字段、特权助手操作或 agent RPC。`askForPassword`（解锁是否需要密码）只被读取用于诊断，永远不会被写入——有没有这条测试兜住：`LockEvidenceTests.testAskForPasswordIsOnlyEverRead`。屏保设置写在子账号自己所属的 ByHost 偏好里，有记录、可还原；如果你自己已经把它设为「永不」，AgentSpace 不会改写它，也不会声称那是它做的。
