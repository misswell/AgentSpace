# 0.1.76 — 登录等待每一种状态都有自己的十分钟，锁屏除外

请更新 AgentSpace 到 0.1.76，并允许它接着更新 Worker（可能需要一次 macOS 管理员授权）。这一版的改动都在 App 侧的登录窗口里；如果你还没升到 0.1.75，那两行诊断修正在 Worker 侧，所以让它把 Worker 一起更新掉才算完整。

**这一版做了什么**

- **修正 0.1.75 的一处过头说法。** 0.1.75 写的是「一旦 macOS 交出了桌面会话，等待不再有时间上限」。那句话是为了解决真问题——解锁只有人自己能做，一次还在正常推进的登录不该因为人在锁屏前磨蹭就被报成失败——但它把不适用的规则一起放开了：如果会话有了、Worker 却始终起不来，窗口会永远转下去，既不成功也不失败。现在时钟改按状态计时（每种状态十分钟），并且**只有「桌面还锁着」这一种是开放式的**，因为只有它的结束取决于人。其余三种（macOS 还没交出会话、Worker 没上线、桌面没就绪）都是 AgentSpace 自己的活，必须给出一个结论而不是空转。
- **放弃的时候会记下是哪个状态。** 界面上仍是同一句超时提示，日志里多一行 `sign-in gave up after 10 minutes in one state: …`（`log show --predicate 'subsystem == "com.agentspace.app" AND category == "login"'`），能说出到底是 Worker 没应答还是会话没出现。
- 等待的原因标签本身没有改动，仍是 0.1.75 的那四句（正在等待 macOS 登录 / 正在启动 Agent Worker / 桌面仍锁着请在系统窗口解锁 / 正在等待桌面完成启动）。

**这一版没有解决什么**

关闭屏幕共享登录窗口的那一刻，macOS 仍会立刻锁一次桌面，那是 Apple 的 `ScreensharingAgent` 在最后一个观看者离开时直接请求 loginwindow 上锁，任何屏保设置都挡不住。这一版也没有让锁屏变成可跳过的东西：桌面锁着的时候窗口会一直等下去，直到有人解锁——这是刻意的，多久输完密码不由 AgentSpace 决定。

**安全边界**

本版没有新增任何密码入口、密码日志字段、注册表字段、特权助手操作或 agent RPC。超时只是**报告**：它不解锁、不写任何偏好、也不替你关掉 macOS 那个系统窗口（提示语会请你自己关）。`askForPassword` 仍然只读不写。
