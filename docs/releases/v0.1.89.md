# 0.1.89 — 启动 Worker 按一次就够了：助手自己等 launchd 落定

**更新 App 之后，请再换一次特权助手。** 等待 launchd 的逻辑在 root 助手里，0.1.88 的旧助手
仍然只会问一次。打开「登录 / 解锁 Agent」或「诊断」，看到助手需要更新时点「重新安装助手…」，
允许一次 macOS 管理员授权；助手换成 0.1.89 的二进制后，这个修复才开始生效。Worker、CLI 与
协议没有变，已连接的账号不需要重新登录。

**以前要点好几遍，是因为 helper 只问 launchd 一次。** Agent 桌面刚通过屏幕共享登录、或上一次
的 Worker 注册还没拆干净时，launchd 会先回一句「Bootstrap failed: 125: Domain does not
support specified action」——这不是拒绝，是它还没准备好。旧助手把这个中间状态当成最终答案，
包装成 `HELPER_REJECTED` 交给 App，于是同一次「连接账号」在不同瞬间按下成败不同，只能反复点。

**现在一次按下会等它。** 助手在启动 Worker 时，对 launchd 的三种会自行消失的状态（17 已被
登记、112 会话正在建立、125 域还没接受操作）每 0.25 秒再问一次，最多约 10 秒；每次重试 Bootstrap
之前会先把上一次的注册拆掉，成功后再 Kickstart。整个等待在原有的一次 XPC 请求里完成，App 的
按钮只按一次。

**等不出来时说清楚是什么状态。** 如果目标账号确实没有图形会话（`launchctl print` 明确答
「没有这个域」），助手立刻返回，不花那 10 秒；窗口里读到的是
「Agent 账号还没有可用的桌面会话，因此它的 worker 没有启动。请打开该账号的桌面，等它完全启动后
再试。」——错误码是 `SESSION_NOT_READY`（可恢复），不再是 `HELPER_REJECTED`，也不再出现
launchd 的英文原文。真的等满 10 秒仍未接受时，同样落到这句可恢复的提示。别的失败（plist 坏了、
签名不对）不会重试，一次就报。

**没有变的部分。** 助手的操作清单与协议版本没变，没有新增 shell、sudo 或密码路径；
`SESSION_IS_CONSOLE` 的拒绝路径没变；App 不会因为重试而重复启动或替换 Worker 之外的东西。

验证证据见 validation §390（重试只覆盖 17/112/125、预算有上限、缺席会话立刻返回、耗尽后归类为
`SESSION_NOT_READY`、App 与双语资源键的源码断言；层 1–3 的实跑数字见该节）。层 4 不制造助手
故障，因此**真实的一次按下仍只有单元测试与源码断言作证**——这一点照实记在那节。
