# 0.1.95 — 点 Dock 图标，回到主页或 Agent 桌面，不再停在设置

**直接更新 App 即可，这次改动在 App 里。** Worker、CLI、特权助手和 wire 协议都没有行为
变化；正在运行的 Worker 会像往常一样被 App 换成同版本。更新后第一次用「登录 / 解锁
Agent」前，先按一次面板上的「重新安装助手…」对齐版本——和上一版一样，只是对齐，不影响
下面的行为。

**为什么会停在设置。** 旧代码认主窗口的办法是「有工具栏的窗口就是主窗口」。macOS 26 的
设置窗口也有工具栏——每个标签一个按钮（实测 5 个；主窗口是 7 个）——所以设置窗口也被当成
了主窗口。点 Dock 只是激活 App，最后用过的设置窗口就留在最前面；激活时挑「第一个有工具栏
的窗口」也可能挑到它。

**现在的规则。** 每个窗口在内容挂载时登记自己的角色：「主页」或「Agent 桌面」。点 Dock
（以及从菜单栏打开 AgentSpace）只找这两种窗口：有 Agent 桌面在前，就把它带到最前；否则把
主页带到最前；设置窗口没有角色，永远不会被当成目标。如果主页窗口已经被关掉，点 Dock 会
重新创建它（实测：只开着一个设置窗口时点 Dock，主页一个窗口回来；先关掉主页再点，主页也
会回来，且不会多出第二个实例）。

**没改的：** 设置仍从主页工具栏的齿轮或 ⌘, 打开；「用屏幕共享打开该桌面」、登录面板和
Worker 的行为都不变。0.1.93 的「登录成功后自动关窗」和 0.1.92 的「记住密码」稳定端口都在。
AgentSpace 仍然不读、不存密码。

**验证边界：** 这项行为在 AgentUse 会话里用 `/usr/bin/open -a`（与 Dock 点击发送同一个
reopen 事件）实测了三种情形：设置窗口在前、另一个 App 在前、关掉主页之后重新创建；始终
只有一个实例。层 4 也新增一条检查「Dock reopen returns from Settings to the dashboard」，
18 项全部通过。日志里对应 `Dock click showed the work surface …` 和
`Dock click recreated the dashboard: …`。

验证见 validation §396。
