# 0.1.91 — 登录成功后，临时的屏幕共享窗口自己关掉

**直接更新 App 即可，这次改动在 App 里。** Worker、CLI、特权助手和 wire 协议都没有
行为变化，不需要重新登录；正在运行的 Worker 会像往常一样被 App 换成同版本（需要时会有
一次 macOS 管理员授权）。

**「登录 / 解锁 Agent」不再留一个要你自己关的窗口。** 对话框检测到 Agent 桌面已连接后，
会自己退出临时的屏幕共享窗口；子账号保持登录，桌面的查看改走 AgentSpace 自己的
「打开桌面」。对话框里仍然要先输入密码——那个窗口是 Apple 的屏幕共享客户端，密码不经过
AgentSpace，所以这一步不能省。

**「记住密码、自动登录」没有做，也不会做。** 那需要 AgentSpace 保管这个账号的密码，并向
人的会话合成输入；产品规则把密码排除在 AgentSpace 之外（界面上也写着「macOS Screen
Sharing handles the password. AgentSpace does not read or save it.」）。这一个版本的屏幕
共享认证窗口本身也没有「记住密码」选项，所以解锁仍然是人输入一次密码，其余由 App 完成。

**只关「登录 / 解锁」自己打开的那个。** 条件是：屏幕共享是这次登录启动的，而且它没有
第二个窗口。如果屏幕共享本来就在运行（可能是你自己的另一个会话），AgentSpace 不替你
结束它，对话框仍会提示你手动关闭。**「用屏幕共享打开该桌面」保持原样**：那是一个查看和
审批的入口，窗口会一直留着直到你自己关闭；授权向导里内嵌的登录面板同样不关——它就是
要你在这个窗口里批准系统面板。

**关窗不会锁桌面。** Worker 安装期间，子账号自己的「要求输入密码」延迟已经被固定为
「永不」（0.1.77 起，validation §376 实测，本次没有改动锁定策略），所以最后一个查看者
离开不再触发锁屏；窗口是在桌面确认就绪之后才关闭的，未连接时保持原样。

验证见 validation §392：4 个新测试固定了关闭范围与时机，全套单测通过。层 4 的两种
仪器都不会真的登录一次，所以「自动关闭」没有在实机上走过——第一次真实登录就是它唯一的
实机验证，这一点照实记在该节。
