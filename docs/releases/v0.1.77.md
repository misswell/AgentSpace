# 0.1.77 — 登录不会完成了：原因在助手里，不在你的 macOS 上

请更新 AgentSpace 到 0.1.77，**并在更新后允许它重新安装助手**（会要一次 macOS 管理员授权）。这一版的判断逻辑住在 root 助手里，而 App 内更新只替换 `/Applications/AgentSpace.app`：只升 App、不重装助手，登录仍然不会完成。升完之后在「登录 / 解锁 Agent」里如果看到「已安装的助手来自旧版本 AgentSpace」，那正是这一步没做到，按提示去「诊断 → 重新安装助手…」即可。

**这一版做了什么**

- **修好了「已经登录却说你没登录」。** 助手判断子账号有没有图形会话的方式，是在 `launchctl print gui/<uid>` 的输出里找 `com.apple.uisecd` 和 `ATTRS` 这两个字符串。macOS 27 上不成立：2026-10-10 在子账号自己的会话里读到的那份输出是 109,127 字节，开头就是 `gui/503 = {` / `type = login`，而这两个字符串一个都没有（主账号自己那份 145,268 字节也一样）。于是这个判断在这台 Mac 上从来只会回答「没有会话」，登录窗口就一直停在「正在等待 macOS 完成 Agent 账号登录…」——而 macOS 早就让你登录了。现在改问 launchd 自己的答复：退出码，加它自己那行域类型。
- **「问不出结果」不再被说成「你还没登录」。** 这条命令有三种回答：域存在（退出 0 且有 `type = login`）、这个 uid 没有图形域（退出 112，实测 uid 99/599/999999）、以及 launchd 不肯把这个域的打印给调用者看（退出 1，`Could not print domain: 1: Operation not permitted`）。前两种是关于账号的结论，第三种什么也不能说明，现在它单独成为一种等待状态，窗口会说「AgentSpace 无法确认 Agent 账号的桌面会话，正在重试…」，十分钟后给的是「请在 AgentSpace 中重新安装助手后重试」，而不是让你去关屏幕共享窗口。之前这第三种情况被 `try?` 折成了 `false`，也就是被折成了第一种。
- **登录窗口不再拿旧助手空转。** 点「登录 / 解锁 Agent」时会先看一眼应答的助手是不是本版本的那一个；是旧的就直接告诉你去「诊断 → 重新安装助手…」，不再转满十分钟。判断用的是内核对那个应答进程的计算代码签名（不是助手自己报的哈希），所以旧助手无法靠自报把这项检查做绿。
- **修好 0.1.75 里那条读日志的命令。** 等待原因那行原本记在 info 级，这台 Mac 上根本读不到（同一个登录进程、同 subsystem、同 category 只留下了 error 级那行；加不加 `--info` 都一样）。现在降到 default 级，命令就是能用的那一条：`log show --style compact --predicate 'subsystem == "com.agentspace.app" AND category == "login"'`。助手侧也新增一行 `sessionInfo gui/<uid> → exit <n> bytes=<n> domain=graphical|absent|unusable`（category `helper`），这一版到底问到了什么，从日志里就能读出来。

**这一版没有解决什么**

关闭屏幕共享登录窗口的那一刻，macOS 仍会立刻锁一次桌面——那是 Apple 的 `ScreensharingAgent` 在最后一个观看者离开时直接请求 loginwindow 上锁，任何屏保设置都挡不住（§376）。桌面锁着的时候窗口仍会一直等到有人解锁，这是刻意的。另外，root 助手直接打印**别人**的 `gui/<uid>` 域这件事本身没有被实测过（这次的实测分别来自账号自己读自己的域、和主账号读不到别人域那条拒绝）：如果助手其实是被拒的，0.1.77 也不会让你登录成功，但它会明确说「无法确认桌面会话」并在日志里给出退出码，而不是把这件事说成你还没登录。

**安全边界**

本版没有新增任何密码入口、密码日志字段、注册表字段、特权助手操作或 agent RPC，`HelperProtocol` 的操作清单没有变。图形会话的判断仍然是只读的：助手的 `sessionInfo` 照旧必须证明答案里的 username 与 uid 就是本次要登录的那个账号——现在这个校验发生在读会话位**之前**，所以一句关于别人家账号的回答不可能完成登录。`sessionInfo` 的应答只是多了一个可选的 `sessionDomain` 字段（新增字段，方法名与 `protocolVersion` 都没动，旧助手没有这个字段时 App 仍按它的 yes/no 处理）。解锁桌面这件事依旧只能由人在 macOS 自己的窗口里完成，`askForPassword` 仍然只读不写。
