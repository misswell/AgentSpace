# 0.1.65 — 「接管隐藏鼠标」的最后一环：关闭内嵌光标的指令现在一定送达

先「检查更新」。如果你已为重装过助手（Worker 0.1.63 及以上，本机已是 0.1.64），本次不需要再重装；还没装过 Worker 修复的要补按一次「重新安装助手…」。

你实测 0.1.64 后报告「内部光标依然存在」——这次把最后一个未验证的环节查穿了：

- **机制本身是好的**（已实测）：在 AgentUse 会话里用与 Worker 同构的屏幕采集流做了判定——`showsCursor=true` 时移动指针，帧里出现约百余像素的光标痕迹；调用 `updateConfiguration(showsCursor=false)` 后同样移动，帧间差异为 **0 像素**。ScreenCaptureKit 确实会停止把光标画进画面。
- **真正的缺陷在投递**（已修复）：App 发送这条「关闭内嵌光标」指令只有一次机会，而它往往发生在**帧流尚未建立完成**的瞬间——`FrameClient` 当时因为还没有 stream id 直接丢弃了请求，并且**此后再也不重发**，于是画面里内嵌的远端光标一直存在。现在请求会被记住：帧流一建立立即补发，重连后也会再次应用。
- 叠加此前 0.1.63 的两处（能力宣告死在主队列、开关被帧率早退吞掉），「接管隐藏鼠标」的整条链——能力宣告 → 指令送达 → 采集器停画 → 不叠加本地 sprite——现在每一环都有据可查。你自己的光标在任何模式下都不会被隐藏。

验证记录见 `docs/validation.md` §365。装好后请再实测一次：进入画面应只剩你自己的光标，画面内不再出现第二个。
