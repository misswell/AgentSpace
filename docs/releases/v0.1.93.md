# 0.1.93 — 登录成功后，临时共享窗口真的会自己关了

**直接更新 App，更新后先用一次「重新安装助手…」对齐版本**（版本号变了，和往常一样只是对齐）。
如果你上次登录后 Screen Sharing 窗口还留着，**先手动关掉它再点「登录 / 解锁 Agent」**：这次修复
只关「登录前本来没有窗口」的那一个，不会去退出一个已经开着窗口的 Screen Sharing。

**上次为什么没关。** 关窗的判断在数 Screen Sharing 的窗口：只要窗口数 ≤ 1 就退出这个 App。
但 macOS 的窗口服务器对一个连接窗口会列出 **5–11 个 layer-0 窗口**——0×0 的占位、整屏宽的
1920×30 条、隐藏的「所有连接」窗口等。实测（在 AgentUse 会话里对一个回环服务器开一次连接）
一个连接窗口在窗口服务器里是 5–7 个 layer-0 窗口，而 App 自己能看到的窗口（AX）只有 **1 个**。
所以 0.1.92 的日志写着 `it owns 11 windows`，判定「有别人的会话」，就不关了。
第二个原因是：如果 Screen Sharing 进程还开着（上次没关成、或用户手动关了窗口但 App 没退），
旧代码只看「进程在不在」，于是静默跳过——日志里连一行都没有。

**现在的判断。** 用「人真正能看到的窗口」计数：优先用 App 的窗口列表（AX，一个连接就是 1 个，
最小化/在别的桌面也算），读不到 AX 时退到「屏上、有实际尺寸的 layer-0 窗口」。登录前先数一次：
只有**登录前一个可见窗口都没有**，才允许在连接成功后退出 Screen Sharing；如果登录前已经有窗口，
那可能是你自己的会话，绝不动它。

**没改的：** 仍然要经过 Apple 的屏幕共享窗口完成认证（0.1.91 起连接成功后它自动关闭）；「用屏幕
共享打开该桌面」和授权向导仍保留窗口；关窗不会锁桌面（Worker 安装期间该账号密码延迟固定为
「永不」）。「记住密码」的稳定端口修复（0.1.92）不变；若你上次还没重新勾选，这次更新后第一次
登录时再勾一次。AgentSpace 仍然不读、不存密码。

**验证边界：** 层 4 的自动化不会真的登录，所以「连接后关窗」这一下仍要由一次真实登录来验证。
新日志分别是 `sign-in ended the temporary Screen Sharing window: quit requested`（成功）、
`it already owned N visible windows before this sign-in`（登录前已有窗口，按规则没动）、
`it owns N visible windows`（登录后出现了第二个可见窗口）。如果窗口仍没关，把 `Export Diagnostics`
发我，这三行会直接指出是哪一条。

验证见 validation §394。
